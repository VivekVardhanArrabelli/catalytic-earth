# Assembly identities at the design-consumer boundary

**Result: protein-copy identity passes; ligand chemical-feature compatibility
fails in the tested OpenBabel wheel. Do not launch a design from this fixture.**
The source-to-PDB translation preserves T6F's atoms and integer bond orders, but
the delegated ligand reader recognizes six aromatic edges where the retained
dictionary marks eleven. The five thiazolium-ring edges lose their aromatic
flags: C2–N3, C2–S1, C4–C5, C4–N3 and C5–S1. With this tested OpenBabel
molecule, RFdiffusion2's pinned `get_bond_feats` rule would encode these as 1/2
instead of aromatic class 4.
No charges, hydrogens or bonds were changed to make that comparison pass.

This research adapter maps a reviewed assembly selection to distinct PDB
chain/residue keys and derives RFdiffusion2 `contig_atoms` from the same atom
map. It addresses the missing operation after the
[RA95 author-template translation](../ra95_design_reference/atlas_input/README.md):
ordinary assembly expansion supplies coordinates, but manually typing downstream
selectors severs their connection to the selected source copies.

The retained 6HA3 transketolase E160Q/F6P–ThDP case uses
[reviewed study and assembly evidence](../../../data/atlas/assembly_context/6ha3/spec.json).
Both protein copies have source author chain A. The adapter assigns distinct
consumer identities without changing their coordinates or choosing new
catalytic atoms:

| Source selection | Consumer residue | Selected atoms | Use |
| --- | --- | --- | --- |
| Operator 1 Gln160 | A160 | NE2 | Interoperability guidepost |
| Operator 2 Glu366 | B366 | OE1, OE2 | Interoperability guideposts |
| Operator 1 Glu366 | A366 | None | Parsed identity control; excluded from guidepost selectors |
| Operator 1 T6F, label B / author A701 | C701 | Whole deposited heavy component | Single name-selected ligand |

The output contains all nine deposited heavy atoms of each of the three protein
residue instances, plus all 42 deposited T6F heavy atoms. Extra protein atoms are
serialization context, not additional guideposts. Every emitted atom has an
inverse map to its atom-site ID, model, label/author identity and assembly
operator in [the receipt](6ha3/receipt.json). The selected ligand atom is named
`N1,`, including the comma; it is not put through the comma-delimited protein
atom selector.

The [PDB](6ha3/assembly.pdb) encodes the retained T6F component dictionary's
43 heavy bonds (35 single, eight double) using repeated `CONECT` neighbors.
The dictionary's aromatic and stereo descriptors remain in the receipt.
Coordinates, atom occupancies and B factors come directly from the retained CIF
and declared assembly transform. The source-to-PDB check reproduces the full
output and rejects collapsed copy identity, an omitted partner, a selector
redirected to the unexpanded copy, removal of the ligand atom-name comma, and
omitted ligand bonds.

## Scope

This is a source-state translation on exposed development material. Operator-2
coordinates are generated by a deposited assembly transform; the assembly has
no independent experimental support in the retained record. Neither these
three guidepost atoms nor the trapped conjugate is a validated productive
design motif. No inference, sequence design, folding, activity assay or
comparative Atlas-benefit test is performed.

T6F's 32 dictionary-only hydrogens have no coordinate rows and are not generated.
Deposited protein hydrogens, other residues, solvent, and four incident metal
coordination rows involving calcium alt A (occupancy 0.68) and magnesium alt B
(0.32) are omitted. None becomes a covalent bond. T6F heavy-atom occupancies
range from 0.53 to 1.00; they are not alternate labels or joint-state weights.
All 42 ligand atom-site formal charges are unknown. Blank PDB charge fields
and unchanged residue names do not establish the bound protonation state;
consumer template perception must remain separate from deposited evidence.

The [interface](6ha3/interface.json) is deliberately partial. It supplies only
the derived protein atom selectors and ligand name. It contains no designed
length, gaps, complete contigs or launch command. The consumer's ligand-name
filter does not preserve chain/residue provenance internally; this adapter
admits exactly one ligand instance and retains its inverse identity externally.
It does not claim to address multiple same-named ligands independently.

## Reproduce the source translation

These checks need Python and the repository, with no model or network access:

```sh
python3 tools/research_lanes/assembly_input_translation/build_input.py \
  --output-dir /tmp/6ha3-assembly-input-fresh
python3 tools/research_lanes/assembly_input_translation/verify_translation.py \
  --result-dir tools/research_lanes/assembly_input_translation/6ha3
```

The output directory must be fresh. Case-specific selections and scope are in
`6ha3.json`; the adapter reuses the existing assembly projector and checks the
frozen assembly review and source hashes. It refuses unresolved alternate,
insertion, charge, atom-name, component-graph or consumer-identity cases rather
than inventing a choice. This is a bounded research adapter, not a general PDB
conversion service.

## Consumer check and stopping decision

The [protein check](6ha3/polymer-consumer-checks.json) executes the exact
`parse_pdb_lines_target` function and `ContigMap` class bodies from RFdiffusion2
commit `d365cbf4db3958814a9f8e4f6f94fa309dfebc2b`, with pinned literal residue
tables, NumPy and explicitly supplied dependencies. It preserves A160/A366/B366,
selects A160/B366 at reference indices 0/2, and retains the three selected atoms'
masks and coordinates. A366 is present but not selected. The test contig
`A160-160_B366-366` and termini flags exercise the constructor; they are not a
design recipe. This source-extracted check does not import the native modules,
run `ipd.dev.safe_eval`, exercise tensor features or validate the full pipeline.

The [ligand observation](6ha3/ligand-consumer-observation.json) uses the actual
OpenBabel `OBConversion`, PDB `ReadString` and hydrogen-removal operations
delegated to by the pinned ligand loader, without conformer generation. In
`openbabel-wheel==3.1.1.23` on macOS ARM64, whose runtime reports `3.1.0`, all
42 atom names (including commas), elements and coordinates match; all 43 edges
and their 35-single/eight-double orders match. Five aromatic flags differ.
All perceived atom formal charges are zero, whereas the deposit leaves them
unknown; this is consumer behavior, not evidence of neutral bound atoms.

The [execution receipt](6ha3/consumer-execution.json) records versions, source
URLs/hashes, supplied dependencies and the failed import preflight. The official
SIF and full RFdiffusion2 feature pipeline were not run. This observation is
specific to the tested wheel and does not establish a version-independent
upstream defect or its chemical cause. The source translation passes, but the
combined chemical acceptance gate is **rejected** because the actual perceived
graph would change the pinned model's aromatic features. Equal atom/bond counts
would have missed this problem. Close this 6HA3 attempt; do not repair protonation,
add metals, widen the parser harness or start a model run to rescue it.

To reproduce the isolated checks, use the three source URLs and saved filenames
in the execution receipt, plus an isolated Python environment with NumPy and
the recorded OpenBabel wheel. No source or dependency download happens inside
these scripts:

```sh
python3 tools/research_lanes/assembly_input_translation/check_polymer.py \
  --source-dir /path/to/pinned-source-files
python3 tools/research_lanes/assembly_input_translation/check_ligand.py \
  --expected tools/research_lanes/assembly_input_translation/6ha3/ligand-consumer-observation.json
```

`--expected` verifies reproduction of the retained incompatibility; successful
script exit does not mean chemical acceptance. The strongest simple alternative
was manual expanded-PDB selection. This bounded test adds a reversible source
mapping and exposes a consequential consumer mismatch; it does not demonstrate
an Atlas design advantage, a functioning catalyst or new mechanistic evidence.
